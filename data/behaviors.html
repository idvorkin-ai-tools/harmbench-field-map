Every behavior ID

400 text behaviors + 110 multimodal · category, functional type, split and tags · every ID is a permalink, every row deep-links its source line
Two kinds of deep link. Every row carries a stable anchor: data/behaviors.html#<BehaviorID> jumps to that behavior and every harm page uses it. And the last column links the exact line of the CSV it came from on GitHub, so one click takes you from an ID to the behavior text at its source. This site holds the metadata; GitHub holds the words.
Identifiers only, on this site. This table lists the BehaviorID slugs that ship in the HarmBench CSVs, with their metadata. It does not contain the Behavior column, any ContextString, or any image. To read what a behavior actually says, follow its source link into the HarmBench repository, where the dataset is published. To read what a category of behavior is for — which is the useful question — read its harm page.

How the source links work

Each link opens the behavior's own CSV on GitHub in plain view with the line number in the fragment, for example harmbench_behaviors_text_all.csv?plain=1#L42. GitHub highlights that line. Line numbers were computed from the file at main: the header is line 1, and because a hundred of the text behaviors carry a multi-line quoted ContextString, a record can span many physical lines — the link always points at the record's first line, which is where the Behavior column starts. The 400 text behaviors live in harmbench_behaviors_text_all.csv, the 110 multimodal ones in harmbench_behaviors_multimodal_all.csv.

The split column applies to text behaviors only: HarmBench ships a 320/80 test/validation split so that attacks and defenses can be tuned on the validation set without contaminating the reported number. The 110 multimodal behaviors ship unsplit. Tags are sparse by design — only two exist, context on the 100 contextual behaviors and hash_check (paired with book or lyrics) on the 100 copyright ones. Everything else is a standard behavior.
