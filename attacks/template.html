The gradient and LLM-optimizer families answer "how hard can we push?". This family answers a more load-bearing question: how much of HarmBench falls over with no push at all, and what does the standard bag of tricks add on top? A quarter falls over; the famous templates add two points. Every ASR figure you read, your own included, is uninterpretable until you know what the same model scores when you simply ask.

What the family has in common

Four of the five build a test case by string manipulation alone — a template wrapped round the behavior, a rendering of one word, or the behavior verbatim. The fifth, SFS, runs a search loop, but samples natural-language candidates rather than walking token space. Nothing differentiates a loss with respect to the input, which is why three rows carry base_num_gpus: 0 and the two that want GPUs (ZeroShot and SFS, two each) want them for a Mixtral 8x7B attack model, not the target. Four list closed_source in allowed_target_model_types; the exception is SFS, which scores candidates by the target's cross-entropy on a fixed continuation and so needs logits.

One scoring convention decides how you read all four columns. ASR is a per-behavior mean over that behavior's test cases, then averaged over behaviors — so a method emitting five test cases per behavior (ZeroShot, Human Jailbreaks) is scored on the fraction of the five that worked, not on whether any did. "Best of five" would place both considerably higher; the benchmark deliberately does not report it. See the classifier and the pipeline.

ZS — ZeroShot

black box · target never queriedclass_name: ZeroShot5 candidates/behavior, one attack-model call eachTable 6 avg 25.4

An attacker LLM is shown the behavior — and, for a contextual behavior, its context passage — and asked to write prompts that would make an instruction-following model exhibit it. Its reply is prefilled with an affirmative opener starting a numbered list, and sampling stops at the first newline, so each call yields one candidate. There is no feedback at all: the target is never called during test-case generation, which is why this runs against API-only targets.

Attack model mistralai/Mixtral-8x7B-Instruct-v0.1 on 2 GPUs via vLLM, at temperature 0.9, top_p 0.95, presence_penalty / frequency_penalty 0.1, max_tokens 256; the config's num_test_cases_per_behavior: 5 overrides the class default of 100. Pipeline row: mixtral_attacker_llm, behavior_chunk_size: 100 — four chunks over the 400 text behaviors, a decision about how often you reload Mixtral. For contextual behaviors the passage is stitched back onto the front of the generated line: the attack model rewrites the ask, never the evidence.

At 25.4 it is indistinguishable from asking plainly — 0.1 points against a grader with roughly 7% label noise. Per model it is more interesting. On closed targets it is often the best of the cheap methods (GPT-4 0613 at 19.4; on Claude 2.1 its 4.1 is the highest cell in all sixteen columns, though inside the noise). But on many targets it is worse than doing nothing: 33.0 → 28.4 on GPT-3.5 Turbo 1106, 18.0 → 14.8 on Gemini Pro, 65.8 → 60.0 on Zephyr 7B. The grader asks "is this this behavior?", so a rewrite that drifts off the behavior is labelled a failure even when the model complied with the drifted version — the flaw Table 4's third prequalification set exposes in rival classifiers.

Reimplemented from Perez et al. 2022, Red Teaming Language Models with Language Models (arXiv:2202.03286) with an adjusted prompt, per §C.1. Reach for it when you want extra phrasings per behavior against an API target on no budget — a variance probe on DirectRequest, not an attack.

SFS — Stochastic Few-Shot

open weights · forward passes, no gradientsclass_name: FewShot50 steps × 64 candidatesTable 6 avg 38.3

The surprise of the family. The loop: ask the same Mixtral attack model for ten variation prompts; dedupe against everything seen and discard anything under 32 characters; run each survivor through the target and score it by mean cross-entropy on a fixed affirmative continuation from data/optimizer_targets/harmbench_targets_text.json; sort ascending; hand the five lowest-loss candidates back as few-shot examples for the next round. Up to 50 times. The returned test case is the single lowest-loss candidate.

Say that objective out loud and 38.3 stops being surprising. That target file is the one GCG optimises against. SFS is GCG's objective with the gradient removed and an LLM sampler in its place: a fluent proposal distribution steered by being shown its own best-scoring outputs. It needs the target's logits — hence allowed_target_model_types: [open_source] — but never a backward pass.

Knobs: sample_size: 64 surviving candidates per step, n_shots: 5, num_steps: 50; attack generation at temperature 1.0, top_p 1.0, presence_penalty / frequency_penalty 0.1, max_tokens 1024, with a stop string capping each call at ten numbered lines. Separate templates cover plain and contextual behaviors, each with a prefilled opener; contextual candidates get the passage prepended before scoring. behavior_chunk_size: 5, base_num_gpus: 2.

Three things stop the loop: the shots stop changing, no new candidate survives filtering, or the current best produces a completion that does not look like a refusal. That last check greedily generates 32 tokens and tests them against a fixed list of 35 refusal substrings — the AdvBench-style heuristic the paper's own Table 4 shows is a bad grader. It cannot inflate the score, since ASR is still the Llama 2 13B classifier over 512 tokens. It only decides when to stop searching, using a different judge at a different horizon than the one that grades the result.

The payoff: 38.3 — above UAT (30.8), GBDA (29.8) and PEZ (29.0), all white box, and level with GCG-Transfer at 38.8. By slice: 44.3 standard, 56.5 contextual, 6.6 copyright. And the result that should worry anyone shipping a defense — against Zephyr 7B + R2D2, adversarially trained until GCG fell from 69.5 to 5.5, SFS still lands 43.5.

"For some attacks, the improvement conferred by R2D2 is less pronounced. This is especially true for methods dissimilar to the train-time GCG adversary, including PAIR, TAP, and Stochastic Few-Shot."— HarmBench, §6.2

Same origin as ZeroShot, but §C.1 is explicit that this is not the original method: the authors "use an iterative version of the Stochastic Few-Shot method to increase the probability of the target LLM generating a target string". The loss-guided iteration is HarmBench's addition, so 38.3 describes HarmBench's variant. Reach for it when you have weights and cannot afford GCG's 500 gradient steps — or to test whether a gradient-trained defense generalises.

Human — Human Jailbreaks

black box · no model calls to buildclass_name: HumanJailbreaks5 of 114 templates per behaviorTable 6 avg 27.3

The corpus is a single Python list, JAILBREAKS: 114 entries, about 226,000 characters, median around 1,400 characters and longest around 16,000. In-the-wild templates of the Do Anything Now lineage — persona framings, fictional wrappers, rule-override framings. This site reproduces none of them; the structure above is what the file tells you without reading it.

Construction is as simple as it looks: template, blank line, behavior string, with contextual passages joined on first via the same \n\n---\n\n separator DirectRequest uses. Nothing adapts per model, behavior or response. The reported column is random_subset_5 with seed: 1, and the list is reshuffled inside the per-behavior loop, so each behavior draws a different five of the 114 while the sequence stays deterministic. behavior_chunk_size: all_behaviors, base_num_gpus: 0, both target types allowed.

An all_jailbreaks experiment exists (random_subset: -1) and a HumanJailbreaks-all pipeline row for it is commented out as expensive on closed models. It would be: 113 templates × 400 behaviors is about 45,000 completions at 512 tokens, before the classifier pass. 113 and not 114 because -1 is an integer, so the slice JAILBREAKS[:-1] drops the shuffled list's last entry — a harmless off-by-one that never touches the reported column.

At 27.3 the whole celebrated corpus is worth 2.0 points over asking plainly (31.9 standard, 41.4 contextual, 4.3 copyright). The per-model numbers say why, unusually cleanly: across two revisions of the same closed model the column falls off a cliff. GPT-3.5 Turbo 0613 scores 24.5 and GPT-3.5 Turbo 1106 2.8; GPT-4 0613 scores 11.3 and GPT-4 Turbo 1106 2.6; the three Claude models sit at 2.4, 0.3 and 0.3. Public templates, indexed, against vendors who have had them for years.

Be careful what you conclude. Five unadapted templates from a 2023 snapshot, thrown at models trained after it and scored on the mean of the five, fairly measures do the famous jailbreaks still work — largely no. It does not measure can a human jailbreak this model, which involves a person who adapts after each refusal and which HarmBench asks of none of its 18 methods. Source: Shen et al. 2023, "Do Anything Now" (arXiv:2308.03825). Reach for it as a staleness check: a model that still falls to a 2023 template has a problem no adaptive attack was needed to find.

ArtPrompt

black box + one GPT-4 API callclass_name: ArtPrompt1 masking call, 1 test case per behaviornot in Table 6

State the gap first: ArtPrompt has no HarmBench ASR number. It appears nowhere in the arXiv v2 text and in none of the result tables — the headline grid has sixteen attack columns and this is not one. It sits in the repository's method set as a later addition, which is why the repo's 21 method configs and 24 active pipeline entries are a superset of the paper's 18 methods. Anything quoted as "ArtPrompt's HarmBench score" did not come from the paper.

Mechanism, at the level this site will describe it: a masking model is asked which single word in the request carries the sensitive load; that word is replaced by a placeholder and re-presented in a different channel, rendered as ASCII art. A safety layer reading the prompt as text never sees the word; a model able to read the rendering still recovers it. The paper's framing: alignment training assumes prompts are interpreted semantically, and that assumption has a hole. Going further would be a build guide, so the page stops here.

The port's details still inform. masking_model: gpt-4-0613, and masking_model_key is required — the constructor raises without it — so despite base_num_gpus: 0 this method needs an OpenAI account to generate test cases. masking_direction: horizontal by default, vertical available; fontname: cards from a six-item list (gen, alphabet, letters, keyboard, cards, puzzle) that is the intersection of the two renderers — horizontal implements eleven fonts, vertical only those six. behavior_chunk_size: 5, both target types allowed.

Three facts before you trust a number from it. Only the first returned mask word is used, with a code comment saying multi-word masking is unsupported. Candidates containing a space are discarded, and if nothing usable survives the test case falls back to the plain behavior string — it silently degrades to DirectRequest, so a run's real coverage is a fraction you must measure, not assume. And a mask word that is not a literal substring raises. There is vestigial optimiser plumbing too: targets_path is loaded but never read, and each log entry records loss=0.

Primary source: Jiang et al. 2024, ArtPrompt: ASCII Art-based Jailbreak Attacks against Aligned LLMs (arXiv:2402.11753), which also introduces the ViTC (Vision-in-Text Challenge) benchmark the code's class names refer to. Reach for it as a channel test, not a strength test: it asks whether your safety layer only inspects the semantics of text.

DR — DirectRequest

black box · no attackclass_name: DirectRequestno hyperparameters at allTable 6 avg 25.3

The entire method config is placeholder: placeholder, written twice. Nothing to tune because nothing is done: generate_test_cases returns the Behavior string. Pipeline row: experiment_name_template: default, behavior_chunk_size: all_behaviors, base_num_gpus: 0, both model types. Step 1 of the pipeline is CPU string formatting; the whole cost lives in generation and classification.

One detail matters for reproduction. For a contextual behavior it does not send the behavior alone: it sends ContextString, then \n\n---\n\n, then the behavior. That join is shared by Human Jailbreaks, ZeroShot and SFS — an undocumented convention of the method set, not a quirk of one file. A harness that reimplements "just send the behavior" without it is not running DirectRequest, and its floor will be wrong in the direction that flatters every attack measured against it.

"This tests how well models can refuse direct requests to engage in the behaviors when the requests are not obfuscated in any way and often suggest malicious intent."— HarmBench, §C.1

25.3 average, and the per-model range is the finding: 0.8 on Llama 2 7B Chat, 65.8 on Zephyr 7B — two rows the benchmark treats as comparable, eighty-fold apart before anyone attacks anything. Beside them SOLAR 10.7B-Instruct at 61.3 and Mistral 7B at 46.3, against 2.8 for both the 13B and 70B Llama 2 Chat models. Refusal training, not scale, separates them — the point the results page makes across the grid.

By slice, 23.9 standard / 46.2 contextual / 7.3 copyright. Contextual is nearly double standard: paste the passage, ask plainly, and 46% of those behaviors succeed with no attack at all — the sharpest form of the paper's Figure 11 claim that the harder-to-look-up behaviors are the easier ones to elicit. And on the Copyright Violations slice, DirectRequest's 7.3 beats GCG's 4.6 and every gradient column: the MinHash grader only fires on near-verbatim regurgitation, and optimisation pushes a model off verbatim reproduction. Asking politely is a better copyright attack than optimising. (Recomputed averages — the printed Average row in the v2 sub-table contradicts its own cells; see the discrepancy note.)

Its multimodal twin MultiModalDirectRequest scores 69.09 on LLaVA 1.5 and 16.36 on GPT-4V over the 110 multimodal behaviors — the same lesson in a second modality. Reach for it always, first. It is the control, and it is free.

Top to bottom the argument is compact. Let an attacker LLM guess (ZeroShot, 25.4) and you have gained nothing over asking. Give that same attacker a target-string objective and fifty rounds of selection on its own best outputs (SFS, 38.3) and you gain thirteen points and pass three white-box gradient methods — the value of a feedback loop, measured with the attack model held constant.

Zephyr 7B under GCG is 69.5; Llama 2 7B Chat under GCG is 32.5. Read alone, Zephyr looks twice as broken. Read against the floor, Zephyr went 65.8 → 69.5 — barely needed attacking; the adversarial work bought 3.7 points — while Llama 2 7B Chat went 0.8 → 32.5, refusals that hold until someone optimises against them. Opposite security stories, adjacent headline numbers, and only the pair distinguishes them.

Two cautions. The grader agrees with humans about 93% of the time, so roughly 7% of labels are noise: the 2.0 points between Human Jailbreaks and DirectRequest, and the 0.1 between ZeroShot and DirectRequest, are not differences you can defend — the 13 between SFS and ZeroShot are. And over-refusal is measured nowhere in HarmBench: a model that refuses every benign request scores 0 here and looks flawless. Pair DirectRequest with a false-refusal set. The classifier page lists the rest of the gaps.

This family keeps an evaluation honest because each member isolates one variable and none has a compute story to hide behind. DirectRequest isolates nothing — it is the control. ZeroShot isolates rephrasing; SFS, target-guided search with the attack model held fixed; Human Jailbreaks, the public prior of 2023; ArtPrompt, the input channel. Run all five before anything expensive, and the interesting question about your model will usually have been answered by the cheapest one — over the same 510 rows, browsable at the behavior index.
