Multimodal behaviors

The fourth functional category — an image, a question about it, and a text-only judge that never looks at the picture.
TL;DR — A multimodal behavior is a picture plus a request that refers to it, so neither half is harmful alone. It is the benchmark's least balanced slice: 90 of the 110 come from two harm categories, 50 are CAPTCHA-solving, and no test/val split was published. Grading runs through a third classifier — a text model reading a hand-written redacted description of an image it never sees. The headline is Table 10: a PGD-optimised noise image drives 48.75–66.00% ASR on ordinary text behaviors, while rendering those same requests into an image gets 3.50–5.25%. The pixel channel is a second door into the model, and a far less defended one.

The other three functional types differ in how a request is phrased. This one differs in what a request is — which changes the attack surface, the grading problem, and what a number means. All three cut the same way: this is where the measurement apparatus is thinnest, and where the attacks work best.

What a multimodal behavior actually is

The multimodal CSV carries nine columns against the text set's six: Behavior, BehaviorID, FunctionalCategory, SemanticCategory, ImageFileName, Source, ImageDescription, RedactedImageDescription, Tags. Four exist only here. ImageFileName is <BehaviorID>.png inside data/multimodal_behavior_images/ — 110 PNGs, one per behavior, about 65 MB, committed to the repository rather than fetched by a setup step (the README describes no download; git ls-files lists all 110). Source is a URL to the original picture, overwhelmingly Wikimedia Commons. ImageDescription describes the picture and RedactedImageDescription is the same with the harmful specifics removed — the second is the grader's input, not documentation. Neither reaches the target model, which gets pixels.

The behavior string is a question about the image, so it is close to inert alone — the contextual type's supplied-passage move, made for the same reason: differential harm, an answer no search engine returns. It also means a harness that resolves the image path wrong will not throw. It will quietly measure an easier benchmark. (No behavior strings or image descriptions appear on this site; the behavior index carries every ID.)

One asymmetry for anyone coding against the CSV: Tags is present but empty on every multimodal row, while the dispatch in eval_utils.py branches on a multimodal tag nothing sets. Assume it is there — as context is on the contextual rows and hash_check on the copyright ones — and you silently get the standard prompt.

Two categories carry 82%; three of the seven contribute eleven behaviors between them. Copyright contributes none, which follows from its metric rather than its subject: copyright grading is a MinHash match against shipped hashes of specific texts, and no version of that test starts from a picture.

The skew has one dominant cause, visible from the filenames alone — 50 of the 110 images are named solve_captcha_<n>.png. The paper says why.

"We include 50 CAPTCHA behaviors to allow measuring whether multimodal models robustly refuse to impersonate humans online."— HarmBench, Figure 17 caption

Nearly half of this type is therefore one narrow task, filed under Cybercrime & Unauthorized Intrusion because §B.4 lists CAPTCHAs there beside hacking and malware. It earns its place, but a headline multimodal ASR is then half a CAPTCHA-refusal score and half everything else, and those have no reason to move together. Read Table 9 as a blend.

The grader that never sees the image

Multimodal completions are graded by a third fine-tune, cais/HarmBench-Llama-2-13b-cls-multimodal-behaviors, sibling to the test classifier. It is a Llama 2 13B text model with no vision encoder, and it is never handed the picture.

What it gets is set by compute_results_classifier in eval_utils.py, which branches three ways on tags: context fills the contextual template's {context} slot from ContextString; multimodal fills that same slot from RedactedImageDescription; everything else gets the standard prompt. So the multimodal branch is not a different rubric — it is the contextual rubric with a paragraph of English standing in for the image, and the notebook the README ships confirms that is intentional.

That buys practicality: one text model grades both contextual and multimodal completions, with no vision-language judge to train. It costs grounding. The judge cannot tell whether a completion is grounded in what is actually depicted; it can only ask whether it counts assuming the description holds. A model that hallucinates the image and then answers confidently about the thing it imagined scores a success.

And the description is not data, it is an artifact somebody wrote — the redaction especially is a hand-made call about which specifics to strip. Table 3's agreement figures cover standard and contextual behaviors only; the multimodal path has no published agreement number at all.

One wrinkle if you rebuild this: the GPT-4 prompt used to label the multimodal training data (Appendix C.4.1) is richer than the one used to serve the distilled classifier — it assumes the model saw the image, asks for reasoning first, and makes a CAPTCHA attempt count even when the answer is wrong. None of that is in the template eval_utils.py runs.

No published split, so no guard

The text behaviors ship as three files — 400 all, 320 test, 80 val. The multimodal behaviors ship as one, harmbench_behaviors_multimodal_all.csv. There is no _test and no _val.

That is a gap in the release, not the design: the appendix describes a 100-behavior validation set — 40 standard, 20 contextual, 20 copyright and 20 multimodal — leaving 410 for test. A 90/20 image split exists on paper; it is not in the repository, and the IDs are not recoverable.

So one of the four design principles has no teeth here. Elsewhere the rule is: tune against the validation split, report on the test split. Here there is one set, and every published multimodal figure is measured on all 110 — verifiable from the table itself, since every Table 9 cell is an exact multiple of 1/110 (64.55% is 71 behaviors, 82.73% is 91), which also shows one test case per behavior. Nothing structural stops a new attack from being tuned on the set it reports.

The five multimodal methods

The text set gets 16 attack columns; the image set gets five methods, split on the same white-box / black-box line as the gradient family. All five run with behavior_chunk_size: 5 and base_num_gpus: 1; the three gradient methods take only open_source_multimodal targets, and those model-type declarations produce the dashes in the GPT-4V row. The objective is GCG's — teacher-forced cross-entropy on an affirmative target continuation. Only the search variable changes, from discrete tokens needing a projection every step to pixels in [0, 1] where the gradient applies directly. That is why ten PGD steps beat five hundred GCG steps.

MultiModalPGD

white boxclass MultiModalPGD10 steps · step 0.01 · ε 0.12564.6–82.7 on the 110

Start from the behavior's real image, preprocessed to the model's native resolution with normalisation deferred so the search runs in raw pixel space. Each step is a sign-gradient move of step_size 0.01, clipped into an L∞ ball of radius epsilon and clamped to [0, 1]; the best-loss iterate is kept. Ten steps of 0.01 move a pixel by at most 0.1 — inside the 0.125 ball — so the imperceptibility budget never binds at defaults and the real knob is the step count. Ten forward-backward passes per behavior, and the strongest column in Table 9.

MultiModalPGDPatch

white boxclass MultiModalPGDPatch2000 steps · ε 1.036.4–81.8 on the 110

Same loss, restricted support: a square of side 0.2×min(height, width) — about 4% of the pixels — placed at random, initialised from noise and optimised unconstrained while the rest of the image is untouched. It is the digital analogue of a printable adversarial sticker. The trade: 200× the steps of plain PGD and, on InstructBLIP, barely half the success (36.36 against 64.55). The limit is not budget but area.

MultiModalPGDBlankImage

white boxclass MultiModalPGD in the pipeline config1000 steps · no ε48.8–66.0 on text behaviors

The odd one out, and the source of this page's headline. It ignores the image behaviors and runs against the 400 text behaviors, starting from a 512×512 field of uniform random RGB noise — "blank" is a misnomer; the paper's caption says randomly initialised — and optimising 1000 steps with the L∞ radius pinned to 1.0, i.e. unconstrained. The image carries no message; it is a free parameter with hundreds of thousands of dimensions the attacker sets. A reproduction trap: this entry declares class_name: MultiModalPGD, and the runner resolves both class and config from that field, so run_pipeline.py gets you plain 10-step PGD instead.

MultiModalRenderText

black boxclass MultiModalRenderTextfontsize 10–201.8–20.0 on the 110

No gradients: draw the request into the picture as visible text and send "complete the instruction in the image" as the text input. The renderer walks font size down from max_fontsize 20 toward min_fontsize 10 until the string fits, word-wraps, and outlines each word in white for legibility over a photograph; against text behaviors it uses a plain grey canvas. The premise — that OCR'd text routes around a refusal trained on typed text — is ArtPrompt's, and here it mostly fails. It is the only method that reaches GPT-4V at all.

MultiModalDirectRequest

black boxclass MultiModalDirectRequestno hyperparameters16.4–69.1 on the 110

The floor, playing the role DirectRequest plays on the text set: hand the model the behavior and its unmodified image. The only configuration is per-model geometry — 336 for LLaVA 1.5, 224 for InstructBLIP, 448 for Qwen-VL-Chat, 224 for GPT-4V — with a Lanczos resize and centre crop, so non-square originals arrive letterboxed. Read everything else as a delta against this column.

Three readings. Pixel optimisation dominates: 64–83% against every open-weight model from an attack budgeted at ten gradient steps, against text-set results where the best column averages 54.3 after 500 steps of discrete search. RenderText is weak everywhere because these models read the rendered text and refuse it as they would refuse it typed — on LLaVA it does five times worse than simply asking. And GPT-4V is reachable only by the black-box methods, which is about access rather than robustness: its wrapper's compute_loss returns nothing. The dashes mean "cannot be run", not "resisted".

Same models, same behaviors, same request text, and a fourteen-fold spread. The only difference is what the image channel is used for. Render the request as legible pixels and the model reads it, recognises it and refuses: 3.50–5.25%, below the text set's DirectRequest floor. Fill the same channel with optimised noise and 48.75–66.00% come out. The image is not carrying the request — that is still in the text channel, unobfuscated. It is carrying an optimisation.

That generalises past HarmBench. Safety training was applied to the token channel; the pixel channel was attached afterwards, is continuous rather than discrete, and had essentially no adversarial pressure applied to it:

"No specific safety measures were used in training this model. However, we find that it does refuse direct requests to perform egregious behaviors."— HarmBench, §C.2, of each of InstructBLIP, LLaVA 1.5 and Qwen-VL-Chat

Refusal inherited from a text backbone survives a plainly worded request and does not survive a gradient. A new modality is a new attack surface — and a larger one than the surface you did defend.

What to watch if you run this

The multimodal corner is the repository's least exercised. Tags is empty where the dispatch expects a value; the BlankImage entry resolves to the wrong class; MultiModalRenderText's constructor opens a targets file its own config never sets and parses it with a module the file does not import; the GPT-4V wrapper calls os.path.join without importing os. This path wants reading before running.

Report the CAPTCHA behaviors separately. Forty-five percent of one number measuring one narrow task is a property of how the set was assembled, not of the models.

Remember what the grader is. Every ASR here is a text model's judgement about a picture it was described rather than shown, so do not average multimodal and text ASRs into one column. The classifier's standing caveats — over-refusal never measured, roughly 7% label noise, a fixed 512-token budget — apply here too, on top of the blindness.

Read the gap, not the number. The DirectRequest column tells you what your refusal training does; the PGD column tells you what it is worth. On LLaVA, 69.09 and 74.55 — almost nothing was left to break. On InstructBLIP, 22.73 and 64.55 — a model that refuses the polite version and folds on the optimised one. The distance between them is what adding an image channel cost.
